# DSH 实时速率插件 — 需求规格（用户逐条确认，共 16 问）

> 状态：需求已闭环（lead 逐问确认）。本文是实现的唯一需求来源，与实现冲突时以本文为准。

## 1. 一句话目标
在 DSH **桌面端**会话里实时显示当前模型请求的吞吐速率（tok/s），并把每次请求的**校准后真值**按「模型+provider」累积成全局账本，可随时弹窗对比哪个模型/链路更快。

## 2. 用户真实意图（两个诉求，同等重要）
- **A 判活**：生成中想知道模型还在不在动（但**不要**停顿告警，见 §5.8）
- **B 比快**：持续试新模型（4 个以上），要能对比不同模型/不同 provider 的快慢

- ❌ 趋势曲线 / sparkline / 表盘
- ❌ 成本估算 / 缓存命中率 / token 构成拆分
- ❌ RPM / TPM
- ❌ 跨会话并列实时列表
- ❌ OTel 导出、状态栏多段、热力图、余额
- ❌ DOM 注入官方 UI
- ❌ 独立统计页面（用弹窗即可）

## 5. 关键技术约束（来自 forge 侦察 + prove 源码级取证）
1. **安装**：CLI `dsh plugin --profile desktop` 被显式拒绝（Electron 独占 profile）。只能走 GUI Plugins → Add plugin，或 agent 工具 `plugin_manager(action:"install_bundle", target=<绝对路径>)`。**本会话已切 Full access，走后者。**
2. **无构建链**：手写普通 JS 即可，形态 `window.__ModuleLoader__.load({id:<包名>, factory(require){...}})`，只需 `node --check` 过语法。
3. **槽位必须是 `conversation.input.dock`**。`conversation.composer.dock` 渲染时 props 为空、拿不到 sessionId，挂上去会串会话。
4. **`useSyncExternalStore` 的 `getSnapshot` 必须返回 primitive**。直接返回 chat 快照对象会触发 React "getSnapshot should be cached" 死循环。→ 订阅里算好数字，snapshot 只返回数字/字符串。
5. **不要写 `engines.dsh`，不要写任何 `@deepseek-ai/dsh*` peerDependency**。两者都会触发 `evaluatePluginCompatibility` 闸门，版本不满足即 `incompatible-version` 拒装；不写则闸门短路。
6. **`options` 是 deep-frozen**，中间件里写入即抛，不要往 options 打标记。
7. **`sessionId` 是可选字段**：compaction / 起标题等内部调用可能没有，必须处理 undefined。
8. **`ctx.sessionProjections` + `wire.view` 不可能承载流式值**（fold 的是 committed events）。实时值只能来自 `llm/stream` 的 chunk 到达时刻。
9. 宿主侧 `tokenUsage` 投影字段是 `uncachedInputTokens`（**不是** `inputTokens`），`.strict()`。
10. 上下文窗口：`ctx.llm.resolveModel(provider, model).context.contextWindow`。

## 6. 架构裁决（lead 定）
**混合架构**（推翻 recon 的纯客户端推荐，因需求已扩展）：
- **宿主侧**：`ctx.on('llm/stream', (options, next) => ...)` 透传，采集 `sessionId` / `provider` / `model` / 每个 chunk 到达时刻 / 末尾 `usage` → 请求结束时算出校准真值，写全局账本（按 model+provider 分组）。
- **客户端侧**：订阅流式文本长度做实时估算，渲染速率条 + 弹窗；历史数据通过宿主自注册 HTTP 路由读取。

理由：`usage` / `model` / `provider` 三者只有宿主侧有，而 F5/F6/F9/F10 全部依赖它们。纯客户端无法满足。

## 7. 速率算法
- 实时：`rate = Δtokens_est / Δt`，`tokens_est = Δchars / charsPerToken`；EMA 平滑（α≈0.3）；charsPerToken 初值 4，按会话历史校准值滚动修正。
- 结算：`rate = usage.outputTokens / decodeMs * 1000`（decodeMs 从首个 delta 到末尾 usage 的时长；若宿主投影可得 `decodeTokens/decodeMs` 则优先用官方口径对账）。
- 校准回填：请求结束把估算值替换为真值写入账本，估算偏差同时记下（便于日后调 charsPerToken）。

## 8. 账本 schema（建议，实现可微调）
```json
{
  "version": 1,
  "entries": [
    { "model": "...", "provider": "...", "ts": 1761..., "outputTokens": 512,
      "thinkingTokens": 128, "decodeMs": 12300, "tps": 52.0, "estimatedTps": 48.3 }
  ]
}
```
聚合在读取时算（平均/次数/最近/最后时间），落盘只存原始样本。
